Q1: What is the difference between a Docker Image and a Docker Container?
Interviewer's Goal: Tests containerization basics and terminology.

A Docker Image is an immutable, read-only blueprint/snapshot containing the application code, runtime libraries, and system dependencies needed to run software (e.g., postgres:16-alpine).

A Docker Container is an active, runnable instance created from that image. It executes as an isolated process on the host operating system with its own virtual filesystem, environment variables, and network ports.

Q2: In docker-compose.yml, what does "5432:5432" mean? What happens if you change it to "5433:5432"?
Interviewer's Goal: Tests understanding of network isolation and port forwarding.

The syntax is HOST_PORT:CONTAINER_PORT. Docker containers are isolated from the host computer by default. 5432:5432 routes incoming traffic on port 5432 of your local machine directly into port 5432 inside the PostgreSQL container.

If changed to 5433:5432, PostgreSQL inside the container still listens on 5432, but external host applications (like Node.js or psql) must connect via localhost:5433. This is common when another local database already occupies port 5432.

Q3: Why are Docker Volumes critical for databases? What happens to database records without a volume?
Interviewer's Goal: Tests knowledge of container ephemerality and data persistence.

Containers are designed to be ephemeral (disposable). Any data written to a container's internal writable layer is permanently lost when the container is deleted or recreated.

A Docker Volume maps a dedicated storage directory on the host machine's physical disk into the container. This decouples data storage from the container lifecycle—allowing you to stop, update, or destroy containers without losing any database records.

Q4: Why did we choose BIGSERIAL for urls.id instead of a standard SERIAL?
Interviewer's Goal: Evaluates architectural foresight regarding scale and numeric data types.

A standard PostgreSQL SERIAL is a 32-bit signed integer with an upper limit of ~2.14 billion rows (2,147,483,647). A global URL shortening service can easily exhaust this limit over time, leading to primary key overflow errors.

By choosing BIGSERIAL (64-bit integer), the table supports up to ~9 quintillion rows (9 × 10¹⁸). In Day 2, this numeric ID also serves as the seed that Base62 converts into compact 6-character short codes.

Q5: What is a Foreign Key, and why did we add ON DELETE CASCADE on clicks.url_id?
Interviewer's Goal: Evaluates relational integrity and data lifecycle management.

A Foreign Key enforces referential integrity by guaranteeing that a column in one table matches a valid primary key in another table (every click must belong to an existing URL).

ON DELETE CASCADE instructs PostgreSQL to automatically delete all child telemetry rows in clicks whenever their parent record in urls is deleted. This prevents "orphan records" from consuming disk space and skewing future aggregate calculations.

Q6: What is a B-Tree Index in PostgreSQL, and how does it speed up queries?
Interviewer's Goal: Tests query optimization, data structures, and algorithmic complexity.

A B-Tree (Balanced Tree) index organizes column values in a sorted multi-level tree structure.

Without an index, PostgreSQL must execute a Sequential Scan (O(N)), inspecting every single row on disk. With 10 million URLs, this takes hundreds of milliseconds.

With a B-Tree index on short_code, PostgreSQL traverses the balanced tree via binary search in logarithmic time (O(log N)), finding the target row in under 1–2 milliseconds.

Q7: What is the trade-off of indexes? Why shouldn't we index every column?
Interviewer's Goal: Tests understanding of write overhead and real-world system costs.

Indexes are not free. They introduce two distinct costs:

  • Slower Write Operations (INSERT / UPDATE / DELETE): Every write to the table requires the database engine to update and rebalance all corresponding index trees on disk.
  • Storage and RAM Overhead: Indexes consume substantial disk space and must fit into database buffer cache (RAM) for peak speed.
Indexes should only be created on columns frequently queried in WHERE, JOIN, or ORDER BY clauses.

Q8: What is a Composite Index, and why create idx_clicks_url_id_clicked_at on (url_id, clicked_at DESC)?
Interviewer's Goal: Tests multi-column indexing strategy for time-series analytics.

A Composite Index spans two or more columns in a predefined order. Our analytics dashboard repeatedly executes: 

SELECT * FROM clicks WHERE url_id = $1 ORDER BY clicked_at DESC LIMIT 50;
If we had separate single-column indexes, PostgreSQL would filter rows by url_id, and then perform an expensive in-memory sort on clicked_at.

The composite index (url_id, clicked_at DESC) allows PostgreSQL to filter by the URL and immediately stream pre-sorted records directly from the index tree without any sorting overhead.

Q9: Why does the architecture use BOTH PostgreSQL and Redis? Why not just PostgreSQL?
Interviewer's Goal: Tests understanding of In-Memory vs Disk-based storage trade-offs.

PostgreSQL is a persistent, disk-based relational database. It excels at complex relational queries, constraints, and long-term durability, but disk operations typically take 15–40ms.

Redis operates completely in RAM, delivering key-value reads in sub-2ms.

For a URL shortener, redirect performance is critical. We use Redis in front of PostgreSQL (Cache-Aside pattern) to serve hot link redirects in <2ms, and as a lightweight broker for our BullMQ background telemetry queue.

Q10: How did init.sql run automatically when the PostgreSQL container started?
Interviewer's Goal: Tests familiarity with container entrypoint lifecycle hooks.

In docker-compose.yml, we mounted ./backend/db/init.sql into /docker-entrypoint-initdb.d/01-init.sql:ro.

The official PostgreSQL container image features an initialization hook in its entrypoint script: on its initial startup (when the database storage directory is empty), it automatically discovers and executes any .sql files placed in /docker-entrypoint-initdb.d/ before opening up external networking.
